# Sticky Notes v2.0 — Surpassing Microsoft Sticky Notes

> **Goal:** Transform from a proof-of-concept into a genuine competitor by adding the features Microsoft Sticky Notes lacks — note linking, tagging, keyboard-first workflow, markdown export, and optional sync.

**Architecture principle:** Keep `NoteStore` as the single source of truth (JSON file + sync backend). All new features are either:
- **Store-layer** (tags, links, sync) — testable without Tk
- **UI-layer** (resizing, rich text, transparency) — thin Tk bindings

---

## Feature Breakdown

### Tier 1: Minimum viable competitor

| Feature | Priority | Store impact | UI impact | Complexity |
|---|---|---|---|---|
| Per-note resizing (multi-line Text) | High | None | High | Medium |
| Rich text (bold/italic/color) | High | Store RTF or markdown | High | High |
| Always-on-top toggle | Medium | Store `always_on_top: bool` | Medium | Low |
| Transparency slider | Medium | Store `alpha: float` | Medium | Low |

### Tier 2: Genuinely better than MS

| Feature | Priority | Store impact | UI impact | Complexity |
|---|---|---|---|---|
| Note linking + backlinks (graph) | High | Store `links: list[str]` | Medium | High |
| Tags + filter by tag | High | Store `tags: list[str]` | Medium | Medium |
| Keyboard shortcuts | Medium | None | Medium | Low |
| Markdown export | Medium | None | Low | Low |
| Optional sync (git/Dropbox/API) | High | New sync layer | Low | High |

- Modify: `src/sticky_notes/app.py` (render with tags)

- **A)** Markdown (lighter, `tk.Text` tags for display, export to `.md` is trivial)
- **B)** RTF (heavier, but exact fidelity)

    reloaded = NoteStore(tmp_path / "notes.json")
    assert reloaded.all()[0].content == "**bold** text"

def test_rich_text_parses_bold():
    """bold parsing applied to Text widget."""
    # Test: "**hello**" → tag "bold" applied

**Implementation:**
- `Note`: add `content: str = ""` (stores markdown, `text` becomes plain-text fallback)
- `NoteStore._write`: include `content`
- `NotesApp`: replace `tk.Entry` with `tk.Text`, add a `_parse_markdown_to_tags()` method that scans for `**bold**`/`*italic*` patterns and applies `text.tag_add("bold", ...)` / `text.tag_configure("bold", font=...)`

## Phase 5: Tier 2 — Surpassing MS features

### Task 18: Note linking with backlinks

**Architecture:** Each note has `links: list[str]` (list of note IDs it links to). Backlinks are computed by searching all notes' `links` arrays.

**Store layer (testable):**
```python
def test_store_backlinks(tmp_path):
    store = NoteStore(tmp_path / "notes.json")
    a = store.add(id="A", text="Note A", color="yellow")
    b = store.add(id="B", text="Note B", color="pink")
    store.add(id="C", text="Note C", color="cyan")
    # A links to B
    store.update("A", links=["B"])
    # B should show a backlink from A
    backlinks = store.backlinks("B")
    assert "A" in backlinks
    assert "C" not in backlinks
```

**UI layer:**
- In `_refresh`, render a "🔗 Links: [link]" line per note
- Clicking a link jumps to that note in the list (scroll to it, highlight)
- New syntax: `[[note-id]]` or `[[note text]]` → creates a link

**Commit:** `git commit -m "feat: note linking with backlinks (Roam-style)"`

### Task 22: Optional sync

**Architecture:** Abstract sync layer. Pluggable backends:
- `GitSync` — commits to a git repo
- `DropboxSync` — pushes to Dropbox
- `SimpleAPISync` — POST/GET to a REST API

```python
class SyncBackend(ABC):
    @abstractmethod
    def push(self, notes: list[Note]) -> None: ...
    @abstractmethod
    def pull(self) -> list[Note]: ...

class GitSync(SyncBackend):
    def __init__(self, repo_path: Path): ...
    def push(self, notes: list[Note]) -> None: ...
    def pull(self) -> list[Note]: ...
```

**Implementation steps:**
1. Extract sync interface
2. Git backend (uses `subprocess` + `git add/commit/push`)
3. UI: "Sync" button + status indicator
4. Config: store backend type + params in `config.yaml`

**Commit:** `git commit -m "feat: optional git sync backend"`

  14 → 15 → 16 → 17  (resizing → rich text → top → transparency)

  18 → 19 → 20 → 21 → 22

Each task follows strict TDD: write failing test → verify RED → implement → verify GREEN → commit.

### Key design decisions

1. **`Note` grows fields** but stays a flat dataclass — no nested structures
2. **`NoteStore` gains methods** (`search`, `toggle_pin`, `backlinks`, `filter_by_tag`, `export_markdown`) — all pure, testable
3. **Sync is pluggable** — `SyncBackend` ABC means we can ship git sync and add Dropbox later without touching the core
4. **Markdown as content format** — one source of truth for both display (parse tags) and export (is already markdown)
